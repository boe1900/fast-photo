# FastPhoto 测试清单（桌面 Web）

> 目标：在不考虑手机端的前提下，验证“可用”所需的关键路径与回归点。  
> 环境：单机部署，建议准备两个账号（`user_a`、`user_b`）做权限隔离测试。

## 1. 冒烟测试（每次发布必跑）

1. 启动后端与前端，能进入登录页，首次注册可成功创建管理员。
2. 登录后进入时间线，不报错，侧边栏导航可切换各页面。
3. 设置页新增图库并触发扫描，进度可见，扫描完成后时间线有照片。
4. 点击照片可打开查看器，`Esc` 可关闭，`i` 可切换信息面板。
5. 上传 1 张图片成功，时间线可见新照片。
6. 收藏/取消收藏正常，收藏页可同步。
7. 删除到回收站、从回收站还原、永久删除均可执行。
8. 全量 `cargo test` 与前端 `npm run build` 通过。

### 自动化命令

```bash
# 后端测试
cargo test

# 前端构建检查
cd web && npm run build

# E2E（会自动拉起后端:8080 + 前端:3000）
cd web && npm run test:e2e
```

> 首次执行 E2E 可能需要安装浏览器：
> `cd web && npx playwright install chromium`

## 2. 权限隔离测试（重点）

1. `user_a` 与 `user_b` 各自创建图库并扫描。
2. 使用 `user_a` 登录：
   - 访问 `user_b` 的 `photo_id` 详情、原图、缩略图、Live 视频，应返回 `403`。
   - 访问 `user_b` 的相册详情、相册照片、相册删除接口，应返回 `403`。
   - 对 `user_b` 的照片执行收藏/回收站/批量操作，应无权限或不生效。
   - 人脸页中“人物重命名/人物照片/人脸缩略图”不可跨账号访问。
   - 标签接口 `GET/POST/DELETE /api/photos/{id}/tags` 不可跨账号访问。

自动化覆盖：`web/tests/e2e/api-share-authz.spec.ts`（跨用户照片/相册越权场景）

## 3. 重复检测测试

1. 准备两张视觉相同或非常接近的图片，放入图库并扫描。
2. 进入“重复”页面，应出现重复分组。
3. 删除副本后刷新页面，分组数量应减少。
4. 上传流程测试：
   - 上传同名不同内容文件，不应覆盖旧文件（应自动重命名）。
   - 上传后重复页可识别（`phash` 已写入）。

自动化覆盖：`web/tests/e2e/upload-trash.spec.ts`（上传链路 + 回收站恢复）

## 4. 核心功能细节回归

1. 地图页：有 GPS 的照片可显示 Marker 并打开查看器。
2. AI 发现页：
   - `AI 分析照片` 后可见场景标签。
   - 语义搜索可返回相关照片。
3. 文件夹页：只显示当前用户图库内目录与照片。
4. 相册分享：
   - 可获取公开分享信息；
   - 设置密码后，未带 `x-share-password` 请求应返回未授权。
5. 地图页：无 GPS 数据时应展示空态提示。
6. 发现页：应能看到当前用户范围内标签；点击「AI 分析照片」应有明确结果提示（成功或失败）。
7. 文件夹页：应显示上传目录并可进入查看照片。
8. 收藏页：应显示收藏照片，取消收藏后为空态。
9. 重复页：应识别重复分组，删除副本后分组消失。
10. 人物页：新用户/无人脸数据时应展示空态提示。
11. 相册页：可创建相册并删除，删除后回到空态。
12. 设置页：各 Tab 可切换；触发打标签后活动日志可见对应记录。

## 5. 已知差距（当前版本）

1. 存储配置（S3/WebDAV）目前主要是 UI 展示，后端保存/连通性测试未完整接入。
2. 旧历史图片若未重新扫描，可能没有 `phash`，重复检测覆盖不完整。
3. 当前 E2E 已覆盖登录、核心导航、上传、回收站恢复、分享密码 API、跨用户越权、地图空态、发现页标签/AI 按钮行为、文件夹/收藏/重复页面，以及人物空态、相册创建删除、设置页活动日志展示。
4. CI 已配置在 `.github/workflows/ci.yml`，默认执行 `cargo test` + `web build` + `web e2e`。
