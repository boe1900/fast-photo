# FastPhoto 测试清单（桌面 Web）

> 目标：在不考虑手机端的前提下，验证“可用”所需的关键路径与回归点。  
> 环境：单机部署，建议准备两个账号（`user_a`、`user_b`）做权限隔离测试。

## 1. 冒烟测试（每次发布必跑）

1. 启动后端与前端，能进入登录页，首次注册可成功创建管理员。
2. 登录后进入时间线，不报错，侧边栏导航可切换各页面。
3. 设置页新增图库并触发扫描，进度可见，扫描完成后时间线有照片。
4. 点击照片可打开查看器，`Esc` 可关闭，`i` 可切换信息面板。
5. 上传 1 张图片成功，时间线可见新照片。
6. 收藏/取消收藏正常，收藏页可同步。
7. 删除到回收站、从回收站还原、永久删除均可执行。
8. 全量 `cargo test` 与前端 `npm run build` 通过。
9. `GET /healthz` 返回 `status=ok`；任意 API 响应头包含 `x-request-id`。

### 自动化命令

```bash
# 后端测试
cargo test

# 前端构建检查
cd web && npm run build

# E2E（会自动拉起后端:8080 + 前端:3000）
cd web && npm run test:e2e

# E2E（包含 S3/WebDAV 设置页联调 UI）
cd web && FASTPHOTO_ENABLE_STORAGE_UI_E2E=1 npm run test:e2e

# E2E（含登录限流 429 恢复窗口回归，建议 CI 参数）
cd web && FASTPHOTO_ENABLE_STORAGE_UI_E2E=1 FASTPHOTO_LOGIN_LIMIT_WINDOW_SECS=5 FASTPHOTO_LOGIN_MAX_FAILURES=5 npm run test:e2e

# 远程存储主链路联调（MinIO + WebDAV，覆盖上传/原图/缩略图/回收站清空/永久删除）
./scripts/test_storage_backends.sh
```

> 首次执行 E2E 可能需要安装浏览器：
> `cd web && npx playwright install chromium`
>
> 执行远程存储联调前需要安装 Docker Engine/Colima + docker compose 插件 + `jq`。

## 2. 权限隔离测试（重点）

1. `user_a` 与 `user_b` 各自创建图库并扫描。
2. 使用 `user_a` 登录：
   - 访问 `user_b` 的 `photo_id` 详情、原图、缩略图、Live 视频，应返回 `403`。
   - 访问 `user_b` 的相册详情、相册照片、相册删除接口，应返回 `403`。
   - 对 `user_b` 的照片执行收藏/回收站/批量操作，应无权限或不生效。
   - 人脸页中“人物重命名/人物照片/人脸缩略图”不可跨账号访问。
   - 标签接口 `GET/POST/DELETE /api/photos/{id}/tags` 不可跨账号访问。

自动化覆盖：`web/tests/e2e/api-share-authz.spec.ts`（跨用户照片/相册越权场景）

## 3. 重复检测测试

1. 准备两张视觉相同或非常接近的图片，放入图库并扫描。
2. 进入“重复”页面，应出现重复分组。
3. 删除副本后刷新页面，分组数量应减少。
4. 上传流程测试：
   - 上传同名不同内容文件，不应覆盖旧文件（应自动重命名）。
   - 上传后重复页可识别（`phash` 已写入）。

自动化覆盖：`web/tests/e2e/upload-trash.spec.ts`（上传链路 + 回收站恢复）

## 4. 核心功能细节回归

1. 地图页：有 GPS 的照片可显示 Marker 并打开查看器。
2. AI 发现页：
   - `AI 分析照片` 后可见场景标签。
   - 语义搜索可返回相关照片。
3. 文件夹页：只显示当前用户图库内目录与照片。
4. 相册分享：
   - 可获取公开分享信息；
   - 设置密码后，未带 `x-share-password` 请求应返回未授权。
5. 地图页：无 GPS 数据时应展示空态提示。
6. 发现页：应能看到当前用户范围内标签；点击「AI 分析照片」应有明确结果提示（成功或失败）。
7. 文件夹页：应显示上传目录并可进入查看照片。
8. 收藏页：应显示收藏照片，取消收藏后为空态。
9. 重复页：应识别重复分组，删除副本后分组消失。
10. 人物页：新用户/无人脸数据时应展示空态提示。
11. 相册页：可创建相册并删除，删除后回到空态。
12. 设置页：各 Tab 可切换；触发打标签后活动日志可见对应记录。
13. 设置页存储配置：本地路径可测试连通性并保存，成功后有明确提示。
14. 登录安全：连续错误密码触发限流后应返回 `429`，稍后可恢复登录。

## 5. 已知差距（当前版本）

1. 远程存储已接入上传、原图读取、按需缩略图生成、回收站清理、AI 分析、人脸扫描，以及“远端源头扫描入库（含嵌套目录）”；当前主要改进空间是超大目录扫描时的分页与性能优化。
2. 旧历史图片若未重新扫描，可能没有 `phash`，重复检测覆盖不完整。
3. 当前 E2E 已覆盖登录、核心导航、上传、回收站恢复、分享密码 API、跨用户越权，并新增“分享密码 + 回收站 + 越权边界”“分享密码移除后恢复公开访问”“batch 收藏/回收站操作仅影响本人照片”“empty_trash + permanent_delete 权限与数据边界”“重名上传自动重命名 + 清空回收站后可复用原文件名”“相册删除后 share token 生命周期失效”“auth/me token 边界（缺失/格式错误/伪造）”以及“登录限流 429 恢复窗口”组合回归场景；同时覆盖地图空态、发现页标签/AI 按钮行为、文件夹/收藏/重复页面，以及人物空态、相册创建删除、设置页活动日志与本地存储配置测试。
4. CI 已配置在 `.github/workflows/ci.yml`，默认执行 `cargo test` + `S3/WebDAV 联调` + `web build` + `web e2e`。
